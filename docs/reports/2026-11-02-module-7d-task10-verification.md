# ผลตรวจรับ Module 7D Task 10 — ปรับปรุงค่าใช้จ่ายที่รับรองและติดตามส่วนเกิน

สถานะ: ผ่านผู้ตรวจอิสระและ Test, Build, Lint/Format ครบตามหลักฐานท้ายรายงาน

- เพิ่มรอบปรับปรุงที่อ้างรายการรับรองฉบับล่าสุดครบทุกบรรทัด ผู้รับผิดชอบเงินยืนยัน → หัวหน้า → ผู้จัดการโครงการ → ผู้ตรวจการเงิน ทุกครั้ง รวมการส่งกลับและการปรับยอดเป็นศูนย์ โดยไม่แก้ข้อมูลรับรองเดิม
- ลดค่าใช้จ่ายไม่คืนยอดเอกสารระหว่างรออนุมัติ เพิ่มยอดกันเฉพาะส่วนต่างต่อเอกสาร ตรวจวงเงินและยอดคืนที่จองไว้ก่อนส่งและก่อนรับรอง ผลต่างมีผลครั้งเดียว ตัวอย่าง 8,000 → 6,000 ทำให้มียอดต้องคืน 2,000 หลังอนุมัติครบ
- หลังคำขอปิดใช้เคสปรับปรุงแยก คงสถานะและประวัติการปิดเดิม ติดตามยอดรับเพิ่มหรือจ่ายคืนด้วยหลักฐานและผู้ตรวจอีกคน ไม่เปิดวงเงินเดิมและไม่เพิ่มค่าใช้จ่ายใหม่ที่ไม่อ้างต้นทาง
- ส่วนเกินมีรายการติดตามผูกคำขอ เอกสาร และฉบับต้นทาง เช่น ใบ 12,000 กับวงเงิน 10,000 ติดตามส่วนเกิน 2,000 ไม่ตัดยอดร่างเงียบ ๆ ไม่ใช้ใบข้ามคำขอ
- หลายเอกสารใช้ส่วนเกินรวมจากฐานเดียวกัน เก็บ claim/cap และยอดที่ผูกไปแล้ว รวมประวัติที่สิ้นสุดแล้ว ไม่เพิ่มสิทธิ์จากการสร้างฉบับใหม่ เมื่อฐานข้อมูลเปลี่ยนหรือจัดสรรเอกสารไม่ครบให้ทบทวน ไม่เดายอด
- ผลพิจารณาส่วนเกินต้องมีผู้ตรวจการเงิน เหตุผลและหลักฐาน กรณีมีเงินเคลื่อนไหวต้องอ้างรายการจ่ายภายนอกของส่วนเกินนั้นที่ผู้บันทึกเสนอและผู้ตรวจอีกคนรับรอง ไม่ใช้หมายเหตุล้างยอด ไม่สั่งโอนหรือเพิ่มยอดค่าใช้จ่ายรับรอง/วงเงินทดรอง
- ใช้การกันหลักฐานจ่ายซ้ำร่วมกับเคสเดิมใน workspace และตรวจสิทธิ์ปัจจุบัน/การแยกหน้าที่ทั้งชุดคำขอ อัปโหลดหลังปิดได้เฉพาะเป้าหมายที่มีสิทธิ์

ผู้ลงมือ Volta และผู้ตรวจ Mill แยกกัน รีวิวพบ Important I1 การนับส่วนเกินซ้ำหลายเอกสาร แก้พร้อม RED 9 เคส และตรวจซ้ำยืนยัน ADDRESSED ไม่พบ Critical/Important ใหม่ใน diff ที่แก้

ผลเฉพาะโค้ดสุดท้าย: focused 27/27 และ regression ที่เกี่ยวข้อง 102/102 พร้อม full-solution Format ก่อนตรวจรวม ผลรอบก่อนเก็บเป็นประวัติ ไม่ใช้แทนผลชุดสุดท้าย

เพิ่ม migration สองชุดพร้อม scoped constraints และการป้องกันแก้ข้อมูลรับรองแล้ว ระหว่างพัฒนาพบการย้อน migration ใหม่ก่อนตัวเก่าปฏิเสธ ทำให้ schema ฐานทดสอบเปลี่ยนค้าง จึงเพิ่ม guard ก่อนเปลี่ยน schema และตรวจซ้ำ รวมการยืนยันว่าหลังปฏิเสธ downgrade โครงสร้างปัจจุบันยังอยู่ ไม่ migrate ฐานจริง

ข้อจำกัด: การรับรองความจริงของเอกสารผลพิจารณาและเงินจริงยังเป็นหน้าที่ผู้ตรวจ ระบบตรวจสถานะ สิทธิ์ และความเชื่อมโยงของหลักฐาน ไม่มี semantic OCR หรือการเชื่อมธนาคาร ไม่มี UI/API ใหม่ใน Task นี้
