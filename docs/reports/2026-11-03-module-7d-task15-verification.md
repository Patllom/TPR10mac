# ผลตรวจ Module 7D — Task 15: API และ client สำหรับการเคลียร์เงิน

เพิ่ม API และ client สำหรับอ่านข้อมูลและส่งคำสั่งเคลียร์เงิน โดยตรวจ session, MFA และสิทธิ์ปัจจุบันก่อนส่งผลกลับ ข้อมูลที่เปลี่ยนระหว่างเตรียมและส่งตอบเป็น conflict ส่วนการถูกถอนสิทธิ์ตอบปฏิเสธโดยไม่ส่งข้อมูลที่เตรียมไว้

ผู้ใช้อนุมัติขอบเขตเพิ่มเติม: อ่านรายละเอียดเฉพาะคำขอที่มีสิทธิ์ ผู้อนุมัติอ่านเฉพาะรอบ/ฉบับและหลักฐานที่ได้รับมอบหมาย และข้อมูลคำขอเชื่อมโยงต้องกรองสิทธิ์และตรวจซ้ำก่อนส่ง ไม่เพิ่มสิทธิ์รายงานหรือเปิดยอดรวมที่ไม่มีสิทธิ์โดยอัตโนมัติ

เพิ่ม typed commands พร้อม allowlist, ยอดเงินแบบ string, cursor ที่จำกัดจำนวนและผูกคำขอ, หลักฐานของเจ้าของ/ผู้ยื่นแทนโดยไม่เพิ่มสิทธิ์ผู้จ่าย และการรับมือ session เปลี่ยน การยกเลิก และผลคำสั่งที่ไม่ทราบผลใน client

## การตรวจ

ผู้ลงมือ Tesla และผู้ตรวจอิสระ Bernoulli แยกกันตรวจ Task นี้ ผลตรวจซ้ำรอบแรกยืนยัน I1/I2/I3 แก้ครบและไม่พบปัญหาสำคัญใหม่ รอบสองยืนยัน T15-G-I1 แก้ครบโดยไม่เปลี่ยน production workers

การตรวจรอบแรกพบสามข้อสำคัญ: family ขาดหน้าถัดไป, client ตีความข้อผิดพลาดหลัง commit เป็นการปฏิเสธที่แน่นอน และ logic เทสต์คำสั่งซ้ำ 42 ชุด ผู้ลงมือแก้และส่งตรวจซ้ำ พร้อมผลเฉพาะส่วน backend 31/31 และ client 78/78 ที่แยกขอบเขต hash ชัดเจน

ข้อมูลคำขอเชื่อมโยงใช้ cursor ที่เข้ารหัสและผูกบัญชี/คำขอ/เวอร์ชัน ยอดรวมในแต่ละหน้าเป็นเฉพาะรายการที่มองเห็นในหน้านั้น ไม่ใช่การรับรองยอดหรือการเคลียร์เสร็จทั้ง family หน้าอาจว่างแต่มีหน้าถัดไปเมื่อรายการในช่วงนั้นไม่มีสิทธิ์อ่าน

หลักฐาน TDD และชุดทดสอบเฉพาะส่วนอยู่ใน `.superpowers/sdd/2026-10-31-module-7d-settlement-refunds/task-15-report.md` พร้อมคำสั่ง เวลาจริง exit code และ hash ไฟล์ แยกผลก่อนแก้ไขออกจากผลบนโค้ดสุดท้าย ไม่ใช้ผลที่ถูกยกเลิกหรือ compile error เป็นหลักฐานพฤติกรรม RED

## รายการติดตามและขอบเขต

คง M2-R1/R2-C1, HTTPS 504, Minor log, OpenAPI 500, T13-M1/T14-M1 และ T4-M1/T11-M1 สำหรับ Task 18 เพิ่ม T15-REVIEW-M1 คำเตือน EF10102 ไว้ใต้ Minor log และ T15-REVIEW-M2 รูปแบบ validator ไว้ตรวจทั้ง branch รวมรายการย่อย Minor log เดิม T12-M1/T13-REVIEW-M1/T14-REVIEW-M2 การปรับ OpenAPI ใน Task นี้ไม่ใช่การปิดปัญหา OpenAPI 500 ทั้งระบบ

พักทดสอบมือถือจริงและ NAS จริงตามเดิม ไม่ deploy ไม่ migrate ฐานจริง และไม่ push/merge ส่วน UI เป็น Task 16 ยังไม่เริ่ม


## ปัญหาที่พบจากชุดตรวจเต็มรอบแรก

ชุด backend รอบแรกหยุดหลังพบ OpenAPI 500 และ TestServer ถูก dispose จึงไม่ถือว่ารอบนั้นผ่าน สาเหตุที่ยืนยันด้วยเทสต์คือ fixture ที่ไม่สร้างฐานข้อมูลยังเริ่ม worker จริง เมื่อครบ 30 วินาที worker เชื่อมฐานไม่ได้และหยุด host แก้เฉพาะ OpenApiFactory ของเทสต์ที่เกี่ยวข้อง พร้อม regression รอ 35 วินาทีและตรวจ OpenAPI/liveness อีกครั้ง รวมอัปเดตรายการเส้นทางแบบ exact equality สำหรับ API ใหม่ ชุดเฉพาะส่วนหลังแก้ผ่าน 123/123

ความทนทานของ RequestRoutingWorker/SettlementClosureWorker ใน production ต่อ EF transient exception ที่ถูกห่อด้วย InvalidOperationException ยังไม่ได้แก้ในรอบ fixture นี้ ต้องติดตามร่วมกับ OpenAPI 500/การตรวจทั้ง branch ไม่อ้างว่าระบบจริงทนฐานข้อมูลล่มได้จากผลเทสต์นี้
