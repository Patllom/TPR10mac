# ผลตรวจ Module 7D — Task 16: หน้าพนักงานส่งเคลียร์และคืนเงิน

สถานะ: ผ่านผู้ตรวจอิสระและชุด Test, Build, Lint/Format ตามตารางผลท้ายรายงาน

## ขอบเขต

เพิ่มหน้าพนักงานสำหรับรอบเคลียร์ค่าใช้จ่าย หลักฐานรูป/PDF รายการคืนเงิน และการยืนยันส่งครบ โดยใช้สิทธิ์และรุ่นข้อมูลจากเซิร์ฟเวอร์ แยกสถานะตรวจอนุมัติ สถานะตามกำหนดเวลา และยอดเงิน ไม่บังคับถ่ายสดเหมือนการลงเวลา

พบ contract เดิมยังไม่มีสิทธิ์ระดับรอบ/รายการคืนเงิน เหตุส่งกลับพร้อมรายการที่เกี่ยวข้อง และสถานะยืนยันส่งครบ จึงเติม projection ที่จำเป็นภายใต้สิทธิ์เดิม ไม่มีการเพิ่มบทบาท สิทธิ์ดูข้อมูล หรือ migration ฐานข้อมูล

กรณีไม่ทราบผลหลังส่งคำสั่ง ระหว่างอยู่หน้าเดิมจะเก็บ commandId และ payload เดิมในหน่วยความจำให้ผู้ใช้ตรวจผลด้วยคำสั่งเดิมผ่าน idempotency ภายใต้บัญชีเดิม หลังรีโหลดจะกู้เฉพาะรหัสอ้างอิงและให้ผู้ใช้ตรวจ receipt จากเซิร์ฟเวอร์ ไม่ส่งซ้ำอัตโนมัติและไม่ถือว่ารุ่นข้อมูลเปลี่ยนหมายถึงคำสั่งสำเร็จ

## หลักฐานและข้อจำกัด

หลักฐานเฉพาะงานและรายงานตรวจอยู่ใน `.superpowers/sdd/2026-10-31-module-7d-settlement-refunds/` (scratch ที่ไม่ commit) ผลสรุปและเวลาชุดตรวจเต็มบันทึกในรายงานนี้

การทดสอบ HTTPS ใช้พอร์ตพัฒนา 4000 และ production 4001 ตาม fixture ของโครงการ การตรวจ viewport ในเบราว์เซอร์ไม่ใช่ผลทดสอบมือถือจริง

คงรายการติดตาม M2-R1/R2-C1, HTTPS 504, Minor log, OpenAPI 500, T13-M1/T14-M1, T4-M1/T11-M1 สำหรับ Task 18, T12-M1/T13-REVIEW-M1/T14-REVIEW-M2/T15-REVIEW-M1 ภายใต้ Minor log, T15-REVIEW-M2 และความทนทานของ production worker ต่อ EF exception ที่ห่อข้อผิดพลาดการเชื่อมต่อฐานข้อมูล

ยังพักการทดสอบมือถือจริงและ NAS จริง งานนี้ไม่เริ่ม Task 17 ไม่ push/merge/deploy และไม่รัน migration กับฐานข้อมูลจริง

งาน HTTPS 504 ที่ค้างอยู่ก่อนหน้าเก็บไว้ตามเดิม การแก้ fixture ใน Task 16 จำกัดเฉพาะ allowlist ของ spec ใหม่และแยก stage เฉพาะส่วนนั้น

## ผลตรวจอิสระและรอบแก้

ผู้ลงมือ: Turing ผู้ตรวจอิสระ: Schrodinger ตรวจพบ T16-R1 ค่าศูนย์บางรูปแบบทำให้ติดคำสั่งรอผล และ T16-R2 รีโหลดหน้าแล้วรหัสคำสั่งหาย จึงเพิ่มการตรวจค่าก่อนสร้าง pending และเก็บเฉพาะรหัสอ้างอิงที่ไม่มีข้อมูลการเงิน พร้อม endpoint อ่าน receipt ภายใต้สิทธิ์ปัจจุบัน เมื่อยังไม่พบ receipt จะคงสถานะรอตรวจผลและปิดการสร้างคำสั่งทดแทน ไม่ใช้การเปลี่ยนยอดหรือรุ่นข้อมูลตัดสินว่าคำสั่งสำเร็จ

Schrodinger ตรวจซ้ำแล้ว: T16-R1, T16-R2 และช่องว่างหลักฐาน PDF ได้รับการแก้ไข ไม่มี Critical/Important ใหม่ในรอบแก้

ผลเฉพาะส่วนหลังแก้: Node 72/72 และ backend HTTP 37/37 ผ่าน รวมการใช้ PDF ที่ถูกต้องผ่าน PdfValidationProcess จริงในฐานข้อมูลและพื้นที่เก็บทดสอบ ตั้งแต่อัปโหลด แนบเอกสาร/คืนเงิน จนดาวน์โหลด bytes ตรงต้นฉบับ Browser HTTPS ใช้ PNG จริงและทดสอบ full reload หลัง POST commit แต่ response หาย ไม่มี POST ซ้ำอัตโนมัติ

HTTPS dev รอบสุดท้ายจบก่อน build production รอบสุดท้าย และ build จบก่อน HTTPS production โดย source hash ตรงกันทั้งสามขั้น ไม่ใช้ผล build ระหว่าง dev รันเป็นหลักฐานส่งมอบ

คง Minor เพิ่มเติม T16-M1 เรื่องโค้ด UI ที่เขียนอัดแน่นไว้ตรวจรวมทั้ง branch และ T16-M2 คำเตือน EF10102 ภายใต้ Minor log เดิม ผล backend ผ่านไม่ได้หมายความว่า log ไม่มีคำเตือน

ข้อจำกัดการกู้ผล: หากไม่พบ receipt หลังรีโหลด ยังไม่เปิดให้สร้างรายการใหม่ ไม่มี endpoint ละทิ้ง/แทนที่คำสั่งเพิ่มใน Task นี้ การอ่านผลต้องเป็นคำสั่งจากผู้ใช้และผ่านสิทธิ์ปัจจุบัน ไม่มีข้อมูลรายการการเงินเก็บถาวรใน browser storage

ชุดตรวจเต็มพบ Format 4 จุดในเทสต์ PDF และ expected API inventory ยังไม่รวม receipt GET จึงแก้เฉพาะเทสต์ ตรวจซ้ำโดยผู้ตรวจอิสระผ่านทั้งสองรอบ คง assertion เทียบรายการทั้งหมดแบบเท่ากัน เทสต์ Identity/OpenAPI เฉพาะส่วนผ่าน 58/58 รอบที่หยุดหลังพบ failure ไม่ถือว่าผ่านชุดเต็ม
