## สิ่งที่ทำได้

- เริ่มจ่ายได้เมื่อฉบับงวดผ่านตรวจ สิทธิ์ปัจจุบันถูกต้อง ไม่มีเหตุระงับที่เกี่ยวข้อง และยอดกันไว้ตรงกัน จากนั้นล็อกทั้งตัวบุคคลและบัญชีผู้จ่าย
- บันทึกผลได้เฉพาะผู้จ่ายที่ล็อกไว้และยังมีสิทธิ์ ยอดและผู้รับต้องตรงงวด มีวันที่จ่ายและหลักฐานครบ เปลี่ยนยอดกันเป็นยอดจ่ายเพียงครั้งเดียว
- การตอบกลับหายหรือส่งคำสั่งซ้ำไม่สร้างการจ่ายซ้ำ คืนผลคำสั่งเดิมได้โดยตรวจสิทธิ์ปัจจุบัน แม้ไฟล์หลักฐานภายหลังไม่พร้อม
- ตรวจไฟล์นอกธุรกรรมการเงิน แล้วตรวจข้อมูลหลักฐานซ้ำภายใต้ lock ก่อนผูกผลจ่าย ป้องกันข้อมูลเปลี่ยนระหว่างทาง
- เวลาไม่ปลดล็อกเอง เหตุระงับใหม่หยุดการเริ่มจ่ายใหม่ แต่ยังบันทึกผลที่ตรงงวดซึ่งเริ่มจ่ายไปแล้วได้โดยไม่ล้างเหตุระงับ
- ธุรกรรมรวมยอดเงิน ผลจ่าย ประวัติ และผลคำสั่ง หาก commit ล้มเหลวต้องไม่เหลือข้อมูลเพียงบางส่วน

งานนี้เพิ่มบริการและเทสต์ ยังไม่มีหน้าจอหรือ endpoint ใหม่ และไม่มีการสั่งโอนเงินจริงจากระบบ กรณีผลไม่ชัดหรือจ่ายไม่ตรงยังคงล็อกและยอดกันไว้ ไม่สร้างผลสำเร็จเทียม; กระบวนการสะสางเป็น Task 7

## ขอบเขตที่ครอบคลุม

ทดสอบคำตอบหายหลังเริ่มสำเร็จ การส่งซ้ำ คนละผู้จ่ายและหลายบัญชีของคนเดียวกันชนกัน บันทึกโดยไม่เริ่มก่อน ถอนสิทธิ์ รุ่นข้อมูลเก่า หลักฐานหายหรือเปลี่ยนระหว่างตรวจ commit ล้มเหลว การตัดยอดซ้ำ เหตุระงับหลังเริ่ม และเวลาผ่านไปหลายวันไม่ปลดล็อก ใช้ PostgreSQL ใน container และบริการจริง รวมการตรวจว่าไม่มี file I/O ขณะถือธุรกรรมการเงิน

ผู้ควบคุมตรวจส่วนที่อยู่นอก diff เพิ่ม: บัญชีกันวงเงินไม่ให้ Consume ซ้ำ ฐานข้อมูลตรวจขอบเขตยอดและทศนิยมโดยไม่ปัดเงียบ การแก้งวดเดิมไม่รับสถานะ Paying และสิทธิ์ใช้ประวัติตัวบุคคลทั้งชุดคำขอ ผลตรวจไม่ครอบคลุม workflow ที่ยังไม่ได้พัฒนาหรือการโอนเงินจริงภายนอก

ไฟล์โค้ด/เทสต์ที่เปลี่ยนมีสามไฟล์เท่านั้น: `PaymentExecutionService.cs`, การลงทะเบียนใน `FieldAdvanceRegistration.cs` และ `FieldAdvancePaymentExecutionTests.cs` ไม่มี migration หรือการแก้ไฟล์งาน HTTPS 504 ที่ค้างอยู่
