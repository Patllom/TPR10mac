# Module 6C — Task 2: ผูกรูปกับเหตุการณ์และสิทธิ์ของวันทำงาน

วันที่ตรวจ: 26 กันยายน 2026

สถานะ: ผ่านเกณฑ์เทคนิค Task 2 แล้ว โดยยังไม่ใช่การส่งมอบ Module 6C ทั้งระยะ และยังไม่ push/merge

## ขอบเขตที่เปลี่ยน

- `EvidenceBinding.EventId` อ้างเหตุการณ์จริงด้วย FK และตรวจความสอดคล้องเมื่อ commit: รหัสรูป เจ้าของ ประเภทเข้า/ออก เวลา และเจ้าของวันทำงานต้องตรงกัน
- การเผยแพร่ยังต้องผ่านข้อบังคับ 6B เดิม: รูปเต็มและรูปย่อผ่านการตรวจและมีสำเนาใช้งานครบ พร้อม binding ใน transaction เดียวกัน
- จุดตรวจสิทธิ์กลางอ่านจาก binding → event → day แล้วใช้ policy 6A เดิม ไม่มีการใช้ต้นสังกัดบนรูปเป็นทางสำรอง
- รูปเข้าและรูปออกใช้ต้นสังกัดที่ตรึงตอนเข้างาน แม้ย้ายหน่วยงานหรือ workspace ก่อนออกงาน ส่วนข้อมูลบนรูปยังเป็น snapshot ณ เวลาเกิดเหตุการณ์ตามสัญญา 6B
- เจ้าของเห็นรูปตนเอง หัวหน้าไม่มีสิทธิ์รูป HR ต้องมีสิทธิ์ปัจจุบันในหน่วยงานของวันนั้นและ MFA ตาม policy เดิม ผู้ดูแลระบบไม่ข้ามกฎ
- รูปเต็ม รูปย่อ ดาวน์โหลด และการตรวจซ้ำก่อนส่ง bytes ใช้ authorizer เดียวกัน audit อ้าง workspace ของวันทำงาน

## Migration และข้อมูลเก่า

เพิ่ม `20260926084047_BindEvidenceToAttendanceEvents` โดยไม่แก้ migration ประวัติเดิม

ก่อนอัปเกรดจะล็อกและตรวจ binding ที่มีอยู่ หากไม่มี event/day หรือข้อมูลไม่ตรง จะหยุด migration พร้อมข้อความ `Evidence binding preflight` โดยไม่ลบรูป ไม่สร้างประวัติลงเวลาขึ้นเอง และไม่บันทึก migration ว่าสำเร็จ ต้องตรวจข้อมูลที่ไม่ตรงก่อนพิจารณานำขึ้นสภาพแวดล้อมจริง

FK และตัวตรวจความสอดคล้องเลื่อนการตรวจถึง commit ได้ จึงสร้าง binding ก่อน event ภายใน transaction เดียวกันได้ แต่ commit โดยขาด event ไม่ได้

การ downgrade จะหยุดเมื่อมี binding ที่ต้องเก็บรักษา เพื่อไม่ถอดข้อบังคับป้องกันประวัติ ฐานว่างยังทดสอบขึ้น–ลง–ขึ้นได้

## ขอบเขตการทดสอบ

- TDD ยืนยันช่องว่างเดิม: ชุดสัญญา Task 2 ล้มเหลว 13 กรณีและผ่าน 1 กรณีก่อนแก้ production code
- ตรวจสิทธิ์ HR หน่วยเดิม/หน่วยใหม่ทั้งกรณีย้ายหน่วยและย้าย workspace พร้อมตรวจ audit และสิทธิ์เจ้าของทุกชนิดรูป
- ตรวจหัวหน้าไม่มีรูป ข้อมูล event/day หายปฏิเสธการอ่าน และการถอนสิทธิ์ก่อนส่งภาพ
- ตรวจ binding ผิดเจ้าของ ประเภท เวลา หรือรหัสรูป ทำให้ transaction ไม่สำเร็จ
- ตรวจการอัปเกรดข้อมูลเดิมที่ถูกต้อง การหยุดเมื่อข้อมูลไม่ตรง การ downgrade ที่ปลอดภัย และข้อบังคับเดิมของ 6B/Task 1
- ปรับข้อมูลจำลองในชุดทดสอบ 6B ให้มีวันทำงานและเหตุการณ์จริง รวมกรณีเผยแพร่หลังย้ายที่เก็บรูป โดยไม่ลดข้อบังคับ production
