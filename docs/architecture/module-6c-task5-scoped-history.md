# Module 6C Task 5 — สถานะปัจจุบันและประวัติลงเวลาตามสิทธิ์

## ขอบเขตที่ทำ

เพิ่มบริการอ่านสถานะปัจจุบัน รายการประวัติ และรายละเอียดวันทำงาน โดยยังไม่เปิด HTTP endpoint หรือหน้าจอใหม่ งานเชื่อม API อยู่ Task 6

- กรองสิทธิ์ใน SQL ก่อนแบ่งหน้า ใช้วันทำงานและ ID เรียงลดหลั่น ไม่ส่งยอดรวมข้ามขอบเขต
- Cursor ป้องกันการแก้ไขและผูกกับผู้ใช้ session กลุ่มรายการ ช่วงวันที่ และขนาดหน้า
- ช่วงค้นหาสูงสุด 31 วัน รวมวันต้นและวันท้าย ขนาดหน้าตั้งต้น 20 สูงสุด 100
- พนักงานอ่านตนเอง หัวหน้าอ่านลูกทีมตาม membership เดิม HR อ่านหน่วยงานที่ได้รับมอบหมาย ผู้ดูแลระบบไม่มีสิทธิ์อัตโนมัติ
- ใช้เงื่อนไขร่วมกับ policy 6A และลำดับสิทธิ์ตนเอง → HR → หัวหน้า ผู้มีเฉพาะสิทธิ์หัวหน้าไม่มี field รูปใน JSON
- แยกเวลาเหตุการณ์เดิมออกจากเวลาที่มีผล รองรับการต่อยอดคำร้องใน 6D โดยยังไม่เปิดให้แก้ย้อนหลัง
- อ่านและตรวจสิทธิ์ซ้ำใน transaction ที่มีงบเวลา 5 วินาที ไม่อ่านไฟล์ภาพใน transaction และบันทึก audit ตามฐานสิทธิ์โดยไม่ใส่รูปหรือพิกัด

## TDD และการตรวจโค้ด

ทดสอบ RED แรก 18 กรณีล้มเหลวเพราะบริการยังไม่มี จากนั้น GREEN 18/18 เพิ่มการตรวจโดยผู้เขียนพบว่า grant HR อาจหมดอายุระหว่างรอ audit: ทดสอบได้ 200 แทน 404 ก่อนแก้ จึงเพิ่มการตรวจฐานสิทธิ์และสิทธิ์รูปซ้ำหลังสร้างผลลัพธ์ ชุดล่าสุดผ่าน 29/29

กรณีเพิ่มเติมครอบคลุม cursor ข้าม session ของผู้ใช้เดิม วันทำงานตรงกัน การถอนสิทธิ์ที่ได้ lock ก่อน การรอ lock เกินเวลา audit ล้มเหลว รอบเปิดข้ามวัน สถานะครบคู่ตามวันไทย และการเทียบ policy เดิมทั้งหัวหน้า HR สิทธิ์ซ้อน และผู้ดูแลระบบ

Fixture ใช้ PostgreSQL จริงและข้อมูลเหตุการณ์/หลักฐานสังเคราะห์ ทดสอบเฉพาะ reference ของรูปและ JSON ไม่ได้อ้างว่าเป็นการทดสอบไฟล์รูปหรือ NAS จริง ใช้ DataProtection ชั่วคราวเฉพาะ test ส่วนระบบจริงใช้ provider เดิม ไม่เพิ่ม dependency หรือ schema

การตรวจรอบนี้เป็นการตรวจโดยผู้เขียนตามแนวทาง Native การตรวจทั้งสาขาโดยผู้ตรวจอิสระยังอยู่ Task 9
