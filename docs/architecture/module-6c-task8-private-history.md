# Module 6C Task 8 — หน้าประวัติลงเวลาตามสิทธิ์

วันที่ตรวจ: 28 กันยายน 2026 · ฐานโค้ด `3e40f8f` · สาขา `codex/module-6c-online-attendance`

## ผลงาน

- `/portal/attendance#history`: ประวัติส่วนตัวพร้อมรูปและ GPS เพิ่มในหน้าลงเวลาเดิม และมีลิงก์จาก Portal แม้ไม่มีสิทธิ์ลงเวลาที่ Site ในปัจจุบัน
- `/portal/attendance/team`: ประวัติลูกทีม แสดง GPS และไม่สร้างรูปหรือส่งคำขอรูป แม้ได้รับฟิลด์รูปเกินสัญญาจาก API
- `/portal/attendance/hr`: ประวัติที่ API อนุญาตตามหน่วยงานที่ HR ได้รับมอบหมาย พร้อมรูปและ GPS
- วันที่ไทย เวลา Asia/Bangkok วันทำงานตามรายการเข้า คู่ข้ามวัน สถานที่เข้าและออกแยกกัน ฐานสิทธิ์อ่าน และเวลาที่มีผลแยกจากเวลาเหตุการณ์เดิม
- ค้นหาช่วงวันไม่เกิน 31 วัน แบ่งหน้าด้วย cursor ของ API และมีข้อความเมื่อไม่มีข้อมูลหรือบริการขัดข้อง
- หน้านี้อ่านอย่างเดียว ไม่มีการส่งออกประวัติหรือแก้เวลา

รูปเรียกผ่าน endpoint หลักฐานเดิมเฉพาะเมื่อ API ส่ง `EvidenceId` ให้ ไม่รับพาธไฟล์หรือ URL รูปจากข้อมูล API การเปลี่ยนที่เก็บยังใช้กลไก 6B เดิม

## การรักษาสิทธิ์และข้อมูลส่วนตัว

API ของ Task 5–6 และตัวอ่านรูป 6B เป็นผู้ตัดสินสิทธิ์จริง เมนูใช้ `/api/v1/attendance/access` เพราะ `session.permissions` มีเฉพาะสิทธิ์ system จึงใช้แทนสิทธิ์ Attendance ไม่ได้ ผู้ดูแลระบบไม่ได้สิทธิ์ HR อัตโนมัติ

Hook ตรวจบัญชีก่อนและหลังอ่านประวัติ ใช้ `no-store`, same-origin, timeout, AbortController และเลขรุ่นคำขอ ล้างข้อมูลจาก DOM เมื่อซ่อนแท็บ ออกจากหน้า เปลี่ยนบัญชี หรือเริ่มตรวจใหม่ เมื่อกลับแท็บหรือ focus จะอ่านสิทธิ์ใหม่ ผลคำขอเก่าถูกทิ้ง บัญชีที่เปลี่ยนระหว่างอ่านจะโหลดหน้าใหม่ แม้ไม่ได้รับ auth notification

ความผิดพลาด 503 ไม่ทำให้ logout และไม่คงรูป/GPS เดิม ส่วน 401 นำไปเข้าสู่ระบบใหม่ พนักงานและ HR ได้รูปเฉพาะข้อมูลที่ backend อนุญาต หน้าหัวหน้าตัดฟิลด์รูปใน parser อีกชั้นและไม่สร้างองค์ประกอบรูป

Backend ที่ตรวจ: `AttendanceHistoryTests`, `AttendanceHistoryDeliveryTests`, `AttendanceRecordingApiTests`, `EvidenceReadTests`, `EvidenceRevocationTests`, `AttendanceEvidenceBindingTests` ครอบคลุมขอบเขต HR/สายบังคับบัญชา การตัดฟิลด์รูป สิทธิ์ตรง URL รูปที่มีอยู่จริง การถอนสิทธิ์ และการเผยแพร่หลักฐาน ไม่ได้รัน backend ทั้งโครงการใหม่ใน Task นี้

Browser ใช้ HTTPS, Next, session และฐานข้อมูลชั่วคราวจริง ส่วนประวัติและรูปสำหรับการทดสอบ UI เป็นข้อมูลสังเคราะห์ที่ควบคุมเวลา/ข้อผิดพลาดได้ ขอบเขตข้อมูลจริงตรวจแยกด้วย backend integration ด้านบน กรณี Admin ใช้ endpoint จริง กรณีหน้าจอมือถือเป็นการปรับ viewport ไม่ใช่ผลทดสอบอุปกรณ์จริง

เพิ่มสามกรณีหลัง implementation เพื่อขยายความครอบคลุม: ซ่อน/กลับแท็บ, session ขัดข้อง, สลับบัญชีโดยไม่มี notification ทั้งสามผ่าน แต่ไม่อ้างว่าเป็น RED ก่อน implementation

## การตรวจโค้ดและการตัดสินใจ

ตรวจโดยผู้พัฒนาในรอบ Task นี้: เส้นทางอ่านถูกจำกัด, DTO ไม่เผย locator, เมนูไม่ถือสิทธิ์ Admin แทน HR, คำขอเก่าไม่ข้ามบัญชี, focus ล้าง DOM ก่อนตรวจใหม่, pagination ไม่สะสมประวัติข้ามตัวกรอง และหน้ากล้องเดิมยังผ่าน regression ผู้ตรวจอิสระทั้งสาขาอยู่ Task 9

1. เพิ่ม `history-view.ts`, `history-client.ts` และ Node tests นอกเหนือรายชื่อไฟล์หลักใน brief เพื่อแยกการตรวจ DTO/transport ต้นทุนคือดูแล helper เพิ่มสองไฟล์
2. ใช้ access endpoint สำหรับเมนู ต้นทุนคือเพิ่มคำขอและซ่อนเมนูเมื่อบริการตรวจสิทธิ์ไม่พร้อม
3. ทดสอบ UI ด้วยข้อมูลสังเคราะห์และตรวจ policy จริงแยกที่ backend จึงยังไม่ใช่การยืนยันวงจร browser ถึงภาพจริงทั้งระบบ

ข้อผิดพลาดระหว่างตรวจ: ตัวทดสอบรูปเดิมนับไอคอน Next.js รวมด้วย จึงจำกัด selector ใน `#history`; ตัวทดสอบ drop ของหน้ากล้องเคยสมมติว่ามี section เดียว จึงเปลี่ยนให้ส่ง event ไปยัง container กล้องจริง ไม่ลด assertion หรือเปลี่ยนข้อจำกัดกล้อง

สภาพแวดล้อม: ใช้ Node 24.19.0 และ SDK .NET 10.0.401 ตามรุ่นโครงการ SDK ชั่วคราวเดิมขาดไฟล์ จึงใช้ชุด Microsoft รุ่นเดิมที่ดาวน์โหลดใหม่ในโฟลเดอร์ชั่วคราวเฉพาะงาน ไม่แก้ pin ของโครงการ พอร์ต Preview ว่างตอนเริ่มและไม่ได้หยุดบริการผู้ใช้
