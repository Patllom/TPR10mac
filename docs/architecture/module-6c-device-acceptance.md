# Module 6C — แบบตรวจรับอุปกรณ์และสภาพแวดล้อมจริง

คำสั่งผู้ใช้ 17 ตุลาคม 2026: พักการตรวจมือถือจริงและ NAS จริงไว้ก่อน เก็บ checklist นี้ไว้สำหรับกลับมาตรวจ ไม่ถือว่าผ่านหรือยกเลิก และยังไม่รับรอง Production การพักนี้ไม่ขวางการจัดทำแผน6D

สถานะวันที่ 28 กันยายน 2026: **ยังรอตรวจบนอุปกรณ์จริง** เอกสารนี้เป็นขั้นตอนรับงาน ไม่ใช่ผลผ่าน การจำลองกล้อง/GPS และขนาดหน้าจอใน Playwright ไม่ทดแทนรายการด้านล่าง

## เตรียมการ

- ใช้บัญชีทดสอบ พนักงาน หัวหน้าโดยตรง และ HR ที่ได้รับมอบหมาย ไม่ใช้รูปพนักงานจริงใน Git
- เตรียม iPhone/iPad Safari และ Android Chrome ระบุรุ่นเครื่อง ระบบปฏิบัติการ รุ่นเบราว์เซอร์ ผู้ทดสอบ เวลา UTC และ commit ที่ deploy
- ใช้ HTTPS ที่อุปกรณ์เชื่อถือโดยไม่ปิด TLS validation; localhost บนมือถือหมายถึงมือถือ ไม่ใช่เครื่องเซิร์ฟเวอร์
- ผู้ทดสอบอนุญาตกล้อง/พิกัดด้วยตนเอง จัดพื้นที่ทดลองที่ไม่กระทบข้อมูลใช้งาน
- หลังแก้ review ระบบต้องตรวจเฟรมใหม่ด้วย `requestVideoFrameCallback`; เบราว์เซอร์ที่ไม่รองรับต้องแจ้งให้อัปเดตและไม่ส่งเฟรมค้าง ต้องตรวจความเข้ากันได้กับรุ่นอุปกรณ์เป้าหมายจริงก่อนเปิดใช้

## NAS และ Production — คนละเกณฑ์กับมือถือ

NAS ยังรอ share ทดสอบและสิทธิ์ดำเนินการ: ตรวจ mount identity, สิทธิ์ service account, read-only/full/disconnect/reconnect, ย้าย write target และอ่านรูปเดิม, checksum, resume migration และสำรอง/กู้คืน DB+ภาพ+protected configuration ให้สอดคล้องกัน ไม่ถอดต้นทางก่อนตรวจสำเนาเสร็จ ไม่ใช้ local folder อ้างว่า NAS ผ่าน

ก่อน Production ต้องมีผู้รับผิดชอบข้อมูลภาพ/GPS ที่องค์กรแต่งตั้ง การแจ้งพนักงาน การทบทวนสิทธิ์ นโยบาย retention/backup ที่อนุมัติ และผล load/restore บนสภาพแวดล้อมเป้าหมาย ระยะแรกยังไม่ลบหลักฐานอัตโนมัติตามข้อกำหนด แต่ไม่ถือว่าได้ผ่านข้อกำหนดกฎหมายแล้ว
